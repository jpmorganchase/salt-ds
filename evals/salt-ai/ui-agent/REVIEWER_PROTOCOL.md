## Question and boundary

Can the existing native reviewer distinguish the preserved flawed and corrected
project-launch applications, and withhold approval when mandatory evidence is
missing? This is a small diagnostic qualification, not a reliability estimate or
a new evaluation framework. The known cases cannot establish general accuracy.

Use the unchanged shared Salt UI Skill, host's native reviewer profile, installed
Knowledge/CLI/runtime cohort and original project-launch task. The reviewer
remains read-only and uses local retrieval. Do not supply a component checklist,
the expected verdict, prior reviewer output or the repair history.

## Procedure

1. Generate neutral case IDs and freeze their mapping, source/file identities,
   handoff contents, task, profile, Skill, model settings and grading criteria
   before any scored invocation. Independently verify that packets contain no
   prior verdict, case label or result-report path.
2. Run one fresh Codex `salt-ui-reviewer` session per case with explicitly selected
   GPT-5.6 Luna and medium effort. Use the same model effort and time limit for
   every case. Do not carry
   session memory, previous messages or previous outputs between cases.
3. Use a common request to independently assess the supplied task, source and
   evidence, and distinguish approval, actionable findings and incomplete
   verification. It may not name the expected defect or expected case verdict.
   Preserve each initial response; do not coach or retry a scored review.
4. Inspect actual retrieval and image-view events, the substantive findings,
   unsupported claims and the final overall verdict. Missing evidence must not
   be combined with an unqualified overall pass. A host/access failure is
   untested; a time/credit limit or failure to finish the review is incomplete.
5. If Luna misses any required discrimination, run the same three packets and
   unchanged criteria with a fresh, explicitly selected GPT-5.6 Sol reviewer,
   through the same Codex host. Do not escalate a passing
   cheaper reviewer merely to seek a preferred answer. If Sol is unavailable,
   report the precise account/host limitation without changing subscriptions.
6. A reviewer qualifies for the next bounded exercise only after satisfying all
   three cases. If neither qualifies, stop the fresh creation exercise and
   report the observed review failure. Keep smaller agents available for
   bounded implementation; this test does not select a creator model by itself.

The Codex limit is five minutes per review, with at most six scored sessions.
The supervising agent interrupts an unfinished review at the limit. This native
subagent interface exposes no per-session credit cap; report usage only when
available. Use fresh agents without inherited conversation, the native read-only
role, supplied-file/image reads and prepared local Salt retrieval. Inspect actual
tool use and source stability. Native role instructions do not establish
adversarial filesystem isolation. Report
the operational blinding boundary honestly; do not claim an adversarial
filesystem isolation guarantee.

One unscored setup probe may confirm fresh-session authentication, selected
profile/Skill loading, the prepared retrieval permission and image reading.
It may not assess a candidate or receive the scoring key. Resolve setup failures
before scored runs and disclose any remaining host limitation.

### Host amendment before grading

The initial Copilot CLI 1.0.83 setup required its minimum thirty-credit cap and
host-default effort. Its one successful setup probe confirmed actual Luna routing,
the Skill, prepared retrieval and image reading. Explicit Luna selection was
unavailable. All three subsequent review requests resolved to `mai-code-1.1-flash`
and were stopped at the routing event, before review tool use or grading. No
supported setting can pin Luna through Auto. Preserve these attempts as ungraded
host-selection failures, not model-quality failures.

Before any scored output, move the qualification to the installed Codex native
Salt reviewer role, which supports explicit Luna and Sol selection. Freeze the
same anonymous packets and scoring criteria with the Codex profile, prompt and
settings. Do not mix host outcomes or interpret Codex qualification as repair of
Copilot. The conditional fresh task, if reached, uses Codex as well.

## Conditional fresh task

After a reviewer qualifies, prepare one new, bounded application modification
with its task and independent acceptance frozen before creator output. Keep the
same supported host and local package cohort. Run the native creator with the
qualified independent reviewer, at most two native repair cycles, and no
lead-supplied Salt choices or supervised source edits. Preserve initial and
repaired results and independently verify the final source, behavior and images.
If it fails, report the failure without promoting a repaired-by-lead result as
autonomous success. Broader trials require a separate decision.

## Recorded outcome

Record per-case model, actual effort, invocation completion, findings and
verdict, local retrieval and viewed evidence, source stability, elapsed time
and available host usage. Separate missing evidence from incorrect findings.
Summarize results and limits in an authored aggregate report. Human workflow
promotion reviews, the maintainer exercise and release authority remain outside
this diagnostic qualification.
