# Salt Doctor consumer pilot

This is a conditional evaluation protocol, not permission to contact consumers,
install Salt tooling in another repository, use participant models, or release
Doctor. Plan 005 Unit 02 must first prove the exact packed candidate. A
`CUT_DOCTOR` result ends the proposal; a `DEFER_CONSUMER_ACCESS` result ends the
unit without outreach; only `READY_CONSUMER_PILOT` can make Unit 005/03
eligible for a separately authorized dispatch.

## Technical boundary

Build and pack the candidate once, then exercise the installed CLI on Linux
Node 22 and 24:

```sh
yarn build:ai-tooling
yarn check:ai-tooling:pack -- --report dist/salt-ai-pack/plan-005-doctor.json
yarn eval:salt-ai:doctor:performance
yarn eval:salt-ai:doctor:packed
```

Dependency installation and candidate materialization may use explicitly
approved access. Every Doctor invocation is offline under the repository
network blocker. The smoke covers the installed binary plus CommonJS and ESM
exports, both private scanner workers, all six physical fixtures, source/packed
semantic parity, and read-only behavior. It must also reject a blocked network
attempt and each missing worker artifact.

The coarse performance sample uses three warm-ups and 12 fresh measured
processes. It is a single-host operational observation. Every measured run must
be complete; no run may exceed 5,000 ms; the 11th ordered sample must be at most
3,000 ms and 256 MiB for wall time and peak RSS respectively. These limits are
fixed. A trustworthy miss is `CUT_DOCTOR`, not permission to rerun until a
favorable sample appears or to raise a threshold.

## Authority and data boundary

Before any outreach, obtain named product/research, privacy, retention, storage,
and participant-contact authority. Missing any of those authorities requires
zero outreach, zero cohort/task counts, and the frozen empty assignment and
comparator-map digests. The validator rejects activity recorded without that
pre-contact authority.

The tracked access summary contains only closed booleans, digests, and aggregate
counts. Do not commit participant or team aliases, repository identities or
URLs, source, diffs, prompts, outputs, model transcripts, credentials, or
private paths. Participant-level material belongs only in the approved private
store and must be deleted at the consented expiry.

Validate an authorized aggregate with:

```sh
yarn eval:salt-ai:doctor:pilot:validate
```

A valid but incomplete authority, consent, access, cohort, or task threshold is
`DEFER_CONSUMER_ACCESS`; it is not evidence that Doctor lacks product value.
Only the exact candidate/protocol/grader/assignment digests accepted by Unit 02
may be dispatched to the four-pair pilot.

## Claim boundary

The pilot compares the integrated candidate with each participant's frozen
normal Salt workflow. It does not isolate Doctor's causal effect and cannot
support statistical-significance, broad-generalizability, or competitor-
superiority claims. Synthetic repositories and tasks invented to trigger
Doctor are not substitutes for authorized consumer evidence.
