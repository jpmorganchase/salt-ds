# Salt Migrate

Migration is an agent-owned procedure for translating existing UI or a structured
source outline to Salt while preserving task flow and important states. Salt MCP
provides canonical evidence and bounded analysis only.

## Procedure

1. Load `core.md` and inspect the source UI, behavior, states, hierarchy, and
   caller-authorized project conventions.
2. Describe the migration goal and identify the Salt claims that require exact
   evidence.
3. Retrieve canonical records for the target components, patterns, tokens,
   packages, and composition. Do not send raw images to the server; first turn
   visual input into a host-owned structured description.
4. Ask the user about material ambiguity or behavior that cannot be established
   from the supplied source.
5. With authorization, translate toward canonical Salt rather than cloning the
   foreign library's styling.
6. Submit changed text for bounded review and run the repository's relevant
   compile, runtime, interaction, visual, and accessibility checks.

## Rules

- Preserve critical actions, states, hierarchy, and task flow.
- Do not invent a Salt equivalent where the evidence is missing.
- Do not add dependencies or change project configuration unless authorized.
- Report what was translated, what evidence supports it, and what remains
  unverified.
