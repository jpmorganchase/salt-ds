# Semantic icon provider

`SemanticIconProvider` lets an application replace icons for shared roles, such as success, close or expand. It affects Salt components that use the semantic mapping; directly imported icons are unchanged. Salt supplies defaults, so the provider is only needed when customizing them.

## Choose a replacement

Preserve the role's meaning, direction and visual emphasis. Compare related states together at 12px, including light and dark backgrounds and the actual component context. Success, warning and error must remain distinguishable without relying on color alone.

Custom icon components should forward sizing, styling and accessibility props so the consuming control can retain its intended appearance and accessible name. Follow the [icon design guidance](https://www.saltdesignsystem.com/salt/foundations/assets/icon-design) for custom artwork.

## Override selected roles

Supply a partial `iconMap`. Unspecified roles retain Salt's defaults. This example uses an outline success icon while preserving the success meaning:

```tsx
import { SuccessCircleIcon } from "@salt-ds/icons";
import { SemanticIconProvider } from "@salt-ds/core";

const customIconMap = {
  SuccessIcon: SuccessCircleIcon,
};

const App = () => (
  <SemanticIconProvider iconMap={customIconMap}>
    {/* Application components */}
  </SemanticIconProvider>
);
```

The [SemanticIconMap interface and default mapping](https://github.com/jpmorganchase/salt-ds/blob/main/packages/core/src/semantic-icon-provider/SemanticIconProvider.tsx) list the available roles and their current defaults.

## Use the mapping in a custom component

Use `useIcon` to obtain the component for a role. The containing control supplies its accessible name; its icon can be decorative.

```tsx
import { Button, useIcon } from "@salt-ds/core";

const ExpandButton = () => {
  const { ExpandIcon } = useIcon();

  return (
    <Button aria-label="Expand">
      <ExpandIcon aria-hidden />
    </Button>
  );
};
```
