Salt components can be imported directly from React Server Components, such as pages and layouts in the Next.js App Router.

Salt marks its modules that use React with the `"use client"` directive, so its components render as Client Components. A Server Component can render them and pass them props that can be serialized, such as strings, numbers and JSX elements.

```tsx
import { Button, StackLayout, Text } from "@salt-ds/core";
import { AddIcon } from "@salt-ds/icons";

export default function Page() {
  return (
    <StackLayout>
      <Text>Rendered from a Server Component</Text>
      <Button>
        <AddIcon aria-hidden /> Add
      </Button>
    </StackLayout>
  );
}
```

## Pass functions from a Client Component

Server Components can’t pass functions or classes to Client Components. This includes event handlers, such as `onClick`, render prop callbacks and the `DateAdapter` prop of `LocalizationProvider`. Pass these from your own Client Component, marked with `"use client"`.

For example, to use the date components, set up `LocalizationProvider` in a Client Component:

```tsx
"use client";

import { AdapterDateFns } from "@salt-ds/date-adapters/date-fns";
import { LocalizationProvider } from "@salt-ds/date-components";
import type { ReactNode } from "react";

export function DateProvider({ children }: { children: ReactNode }) {
  return (
    <LocalizationProvider DateAdapter={AdapterDateFns}>
      {children}
    </LocalizationProvider>
  );
}
```

Then render it from a Server Component, such as your root layout, around the components that need it.

## Use utilities and constants

Utilities in modules that don’t use React, such as `makePrefixer`, can be called from Server Components.

Utilities and constants that are defined alongside components or hooks can only be used in Client Components. These include `resolveResponsiveValue`, `getCurrentBreakpoint`, `DEFAULT_ICON_SIZE` and `countryToComponentMap`. To use them, move the code that uses them into a Client Component.
