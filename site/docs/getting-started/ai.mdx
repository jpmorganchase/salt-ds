Salt's MCP package is undergoing a breaking redesign. Public onboarding and
release are paused until the minimal surface and its packed release path are
verified.

## What Salt MCP will own

The server owns:

- canonical Salt facts and content;
- deterministic search and exact resources;
- bounded inspection of caller-authorized project state;
- bounded analysis of submitted code; and
- claim-level evidence and provenance.

The host agent owns:

- dialogue and intent resolution;
- planning and design choices;
- code generation and editing;
- implementation authorization;
- iteration; and
- decisions about file, repository, implementation, or task completion.

## Read-only surface

The server exposes exactly three tools:

- `search_salt` for bounded catalog discovery and digest-bound resource links;
- `inspect_salt_project` for caller-authorized package, installation,
  workspace, and policy facts; and
- `review_salt_code` for analysis of submitted source text only.

MCP resource discovery returns the curated, digest-bound catalog manifest.
Exact records remain addressable through the catalog resource template and
links returned by search or parent records. Record reads link larger payloads
to verified `content` resources rather than embedding them by default. The
server advertises the catalog and project-policy templates, and the immutable
packaged catalog has no resource subscriptions or list-change notifications.
The stdio server negotiates the current `2026-07-28` protocol while retaining
the documented legacy revisions headed by `2025-11-25`.

The manifest keeps the server package version, catalog version and digests, and
negotiated MCP protocol revision distinct. The server does not expose a
capability manifest or server-owned creation or migration workflow.

Creation and migration remain possible as agent-owned procedures: inspect the
project, retrieve exact Salt evidence, make only authorized edits, submit changed
text for bounded review, and run the repository's real compile, runtime,
interaction, and accessibility checks. No MCP response authorizes edits or proves
the broader task complete.

## Trust boundary

The current CLI runs locally with the filesystem permissions of the account that
launches it. `root_dir` selects where discovery starts; it is not yet a sandbox
or authorization boundary. Use the least practical privileges and sandbox the
process for untrusted repositories.

Repository policy is untrusted project data. It must not be treated as
server-authored instructions, safety claims, or mutation authorization.

Remote/shared embedding and named-host interoperability are not advertised until
allowed-root containment and host evaluation have passed.

## Release status

Do not install or recommend this branch as a public release. Public setup
instructions will return only after:

- the minimal final protocol surface is verified from the exact tarball;
- catalog and resource correctness gates pass;
- no expected failure is counted as success; and
- real-host/model evaluation is available.

The implementation baseline and known semantic failures remain internal until
the release verification work is complete.
