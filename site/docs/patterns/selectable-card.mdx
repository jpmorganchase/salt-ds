## When to use

Use the selectable card pattern for options that:

- Are the main focus of your UI (and space permits).
- Benefit from an illustration or explanation.
- Should support quick interaction on mobile, with a large tap target.

<Callout status="success" title="Best practices">

- Consider using other form controls, such as [`Switch`](/salt/components/switch), [`RadioButton`](/salt/components/radio-button), [`Checkbox`](/salt/components/checkbox) or [`Dropdown`](/salt/components/dropdown), when you have insufficient space or many options that won’t be visible on screen at the same time.
- Use [`Card`](/salt/components/card) instead if your interactive elements are contained within the card content, such as a button or a link.
- Use [`LinkCard`](/salt/components/card/examples#link-card) instead to navigate users when clicking on the entire card.

</Callout>

## How to build

### Anatomy

The following elements are used in a selectable card:

1. **Interactable card**: The whole card is the selection control. `InteractableCardGroup` supplies single- or multiple-selection behavior, and each `InteractableCard` exposes its selected state and keyboard interaction.
2. **Image**: Images are optional and should span the full width of the card. Refer to [`Card`](/salt/components/card) documentation for more guidance on using images.
3. **Title**: The title can be accompanied by an optional icon or avatar.
4. **Selection indicator**: Use `RadioButtonIcon` for single selection or `CheckboxIcon` for multiple selection. These visual indicators are not interactive; set `aria-hidden` because the card already exposes its selected state. Supporting text may help users decide.

### Card layout

- Compose `InteractableCard` options inside `InteractableCardGroup`, and give the group a label using `aria-labelledby` or `aria-label`. Follow the [Card interaction guidance](/salt/components/card/usage#interactable-elements).
- Use a stack layout to display the card’s content in a column, with `gap={1}` (`--salt-spacing-100`) between the title and the selection indicator.
- Keep the card as the only interactive control. Do not nest `RadioButton`, `Checkbox`, buttons, or links inside it. Keep each indicator's `checked` value in sync with the group's selection.
- Update the padding if you need a small or a large card. Refer to [`Card`](/salt/components/card) documentation for more guidance on custom padding.

<Callout status="success" title="Best practices">

- Be consistent in your use of images across all selectable cards within a group. Either all contain an image, or none do.
- Keep your cards' titles and descriptions succinct, using similar amounts of text in each card.
- By default, titles and supporting content are left aligned inside the card when using left-to-right languages like English. For text alignment alternatives, refer to the [typography foundation](/salt/foundations/typography).

</Callout>

## Single selection

Use `InteractableCardGroup` without `multiSelect` for a mutually exclusive set of options. Each card behaves as a radio button, and the group manages selection and arrow-key navigation. Use `RadioButtonIcon` to show the selected option, as in the [single-selection example](https://storybook.saltdesignsystem.com/?path=/story/patterns-selectable-card--single-selection).

## Multiple selection

Set `multiSelect` on `InteractableCardGroup` when users can choose several options. Each card behaves as a checkbox. Use `CheckboxIcon` to show the selected options, as in the [multiple-selection example](https://storybook.saltdesignsystem.com/?path=/story/patterns-selectable-card--multiple-selection).

<Callout status="success" title="Best practices">
  Include a non-color selection indicator for selected and unselected states.
  Don’t rely on a border or color alone. Use `RadioButtonIcon` or `CheckboxIcon`
  as a visual indicator so the selected state is visible without adding another
  control inside the card.
</Callout>

## States

Selectable cards support the following states:

- **Default**: Available option; the card is interactive but not selected.
- **Hover**: Pointer hover highlights the entire card to indicate it can be selected by clicking anywhere in the card.
- **Selected**: Option is chosen; selected styling and the selected radio/checkbox indicator are shown.
- **Disabled**: Option is unavailable; the card and its visual indicator are muted and not interactive.
- **Read-only**: Shown for review; use a static `Card` with text and a visual indicator to communicate the selection state.
- **Read-only (selected)**: Shown for review with the option already selected; use a static `Card` with a selected indicator and text that identifies the option as selected.

`InteractableCard` has no `readOnly` prop. Use a static `Card` for review-only content rather than leaving a selection control active.

## Validation message

When at least one selection is required and the user attempts to proceed without a valid selection, display a [Banner](/salt/components/banner) at the top of the selectable card set to provide immediate, in-context feedback. Show it after a validation event (e.g., Continue/Submit or other field validation), keep it visible until the user makes a valid selection, then remove it automatically.

## Viewport

Adapt card layouts to the user’s screen size. For layout patterns, spacing, and page structure, refer to [Salt’s Layouts guidance](/salt/foundations/responsiveness). On larger viewports, you can show more cards per row while keeping spacing comfortable for click/tap targets. On smaller viewports, show fewer cards per row (or switch to a single column). For breakpoints and responsive behavior, see [Responsiveness](/salt/foundations/responsiveness).

<Callout status="success" title="Best practices">

- Using a repetitive format or grid layout informs users of the selectability of cards, promoting understanding of their interactive functionality and improving accessibility.
- Keep cards in your group consistent in height, regardless of where they are positioned, to maintain uniformity.
- Use consistent horizontal and/or vertical spacing between cards to provide adequate touch/click targets, minimizing the risk of accidental taps or misclicks, while ensuring responsive layout across various viewports.

</Callout>
