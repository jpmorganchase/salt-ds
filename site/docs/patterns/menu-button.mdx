## When to use

Use a menu button when multiple related actions need to be viewed in context but are not necessarily deemed high enough priority to be displayed on screen. When activated, the menu button reveals a list of actions a user can take. The options are displayed across a single level or multiple hierarchical levels, in a cascading menu. Choosing an enabled command invokes the application action and closes the menu; choosing a submenu trigger opens its submenu. Follow [Menu action outcomes](/salt/components/menu/usage#action-outcomes) for pending work and recovery.

Menu buttons are ideal for where space is limited, or if certain actions are not a priority in impacting the page content. They can be positioned alongside headings, within filter bars, or within alternative layouts composed of various elements.

## When not to use

- When the user needs one clear action, use a Button instead of hiding it behind a menu.
- When several actions are high priority and should remain visible, use a Button bar or toolbar instead.
- When users are choosing a value rather than triggering an action, use a selection component such as Dropdown, Combo box, or List box instead.
- When the items navigate users to another location, use Navigation, links, or another wayfinding pattern instead.

## How to build

### Anatomy

A menu button contains:

1. **Menu trigger:** a button that opens the commands; it does not execute a separate default action.
2. **Menu actions:** related commands displayed after the trigger is activated.

<GuidanceCallout type="positive" customPillText="Best practices">
  Use a chevron icon to indicate that the trigger opens a menu of commands.
  Optionally, you can use left-aligned descriptive icons to effectively signify
  a menu item’s purpose.
</GuidanceCallout>

### Layout

- Use a [Button](/salt/components/button) inside `MenuTrigger` to open the menu.
- Use [Menu](/salt/components/menu/usage#composition-and-labels), `MenuPanel`, and `MenuItem` to compose the commands and their labels.

<Diagram src="/img/patterns/menu-button/layout.png" alt="layout" border />

By default, the menu aligns below the trigger at its starting edge. Depending on where the button is positioned within the available space and layout of the interface, the menu will dynamically adjust positions in order for its options to remain visible.

## Menu button

Menu button uses a primary button and is used when actions in the menu are related to the core functionality of an application. The button value is typically a string supported by a chevron icon, or can be an icon-only button, provided the icon is well-known and not likely to be misinterpreted.

## Overflow menu

Overflow menus contain actions that affect a smaller type of content within an interface, such as within cards or data grids. This is typically represented by a three dot icon as the action button. This is useful when space is limited or the interface needs to remain uncluttered to reduce cognitive load.

## Icon-only

Icon-only menu buttons can be configured to contextually align to the product requirements, instead of being displayed as a chevron. See guidance for [button options](/salt/components/button) to select the most suitable button affordance for your application.

## Heading as menu

A menu button beside a heading can expose commands for that section. If the control instead chooses a destination or changes the displayed content, follow [Navigation](/salt/patterns/navigation) or [view switching](/salt/components/toggle-button/usage#view-switching). Vertically align the trigger with its heading and use `--salt-spacing-100` between the button and text.
