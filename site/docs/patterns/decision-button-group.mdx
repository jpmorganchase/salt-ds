## When to use

Use a decision button group when:

- The group represents one compact decision point in a flow.
- The actions have equal priority.
- The buttons achieve single-selection and deselection capability together. 

## When not to use

- One action is clearly primary and the others are secondary; use [Button bar](/salt/patterns/button-bar) instead.
- The actions are unrelated or don't benefit from being grouped visually.
- The group is being used as a page-level action bar. 
- When you don't need deselection, use [Toggle button group](/salt/components/toggle-button/examples) instead. 

## How to build

### Anatomy

A decision button group typically contains two buttons placed together with consistent spacing:

1. **Buttons:** Contain a label, an icon or both. 
2. **Toggle buttons:** Contain a label, an icon or both.

### Layout

- Use [Button](/salt/components/button) to display actions in a decision button group.
- Use [Toggle button](/salt/components/toggle-button) to display actions in a selectable decision button group.

<GuidanceCallout type="positive" customPillText="Best practices">
- Use spacing-100 between buttons. For more information, read Salt guidance on
  [horizontal spacing](/salt/foundations/spacing#horizontal-spacing).
- Don't mix button types in the same group. 
</GuidanceCallout>

### Action buttons

Use a button within a decision button group when each button performs an action and returns to its default state after activation.

### Selectable buttons

Use a toggle button within a decision button group when each button represents a choice or decision. The user is choosing something, and the selected button remains visible as the current value. For example, Like/Dislike or Thumbs up/Thumbs down.

### Deselection

When a user selects an option, any previously selected option in the group should be deselected. This prevents conflicting selections.

## Grouping for accessibility

Group the buttons together visually and semantically so assistive technology can identify the controls as part of one decision or action set. The group should always have an accessible name when the surrounding context does not already make its purpose clear.

Good accessible group names describe the decision being made, not the visual layout. Each button still needs its own accessible name. The group name explains the shared purpose; the button name explains the individual option.
