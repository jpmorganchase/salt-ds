## When to use

Use a decision button group when:

- A user decision is needed on how to proceed with a specific action.
- User feedback or choice needs to be captured.
- The group represents one compact decision point in a flow.
- The choices have equal priority.
- The buttons achieve single-selection and deselection capability together. 

## When not to use

- One action is clearly primary and the others are secondary; use [Button bar](/salt/patterns/button-bar) instead.
- The actions are unrelated such as 'Share' and 'Edit'.
- The group is being used as a page-level action bar. 
- When you want to change the view or state of information or content on the page, use [Toggle button group](/salt/components/toggle-button/examples) instead. 

## How to build

### Anatomy

A decision button group places two choices side by side as a single group:

1. **Choice:** Possible answers to the decision, displayed as a button or a toggle button.
2. **Label:** Text describing the choice. Optional if an icon is present.
3. **Icon:** A visual representation of the choice. Optional if a label is present.

### Layout

- Use [`Button`](/salt/components/button) to display actions in a decision button group.
- Use [`ToggleButton`](/salt/components/toggle-button) to display actions in a selectable decision button group.

- Don't mix Button and Toggle button in the same group.

## Action buttons

Use a button to display the choices when the user's decision is immediately registered and submitted on click, such as Approve/Reject. Each button then returns to its default state, with no selection remaining visible.

## Selectable buttons

Use a toggle button to display the choices when the user's decision needs to remain visible, or is submitted or collected at a later point in the flow. The selected button stays selected as the current value until the user changes or deselects it.

### Deselection

When a user selects an option, any previously selected option in the group should be deselected. This prevents conflicting selections. Users can deselect both decisions if they decide they prefer not to submit feedback.

## Grouping for accessibility

Group the buttons together visually and semantically so assistive technology can identify the controls as part of one decision or action set. The group should always have an accessible name when the surrounding context does not already make its purpose clear.

Good accessible group names describe the decision being made, not the visual layout. Each button still needs its own accessible name. The group name explains the shared purpose; the button name explains the individual option.
