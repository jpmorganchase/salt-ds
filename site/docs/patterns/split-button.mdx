## When to use

Use the pattern for actions with multiple associated commands. Users are able to immediately perform the default action and access supplementary actions, which include more specific or less commonly-used actions.

For example, a paste-focused split button could include:

- **Default action:** Paste.
- **Supplementary actions:** Keep source formatting, Match destination formatting, Paste text only.

## When not to use

- When there is only one action, use a [Button](/salt/components/button).
- When opening the menu is the only action and there is no separate default command, use a [Menu button](/salt/patterns/menu-button).
- When users are choosing a field value or persistent presentation, use the appropriate [selection control](/salt/components/list-box/usage#choosing-a-selection-control) or [view-switching control](/salt/components/toggle-button/usage#view-switching).

## How to build

### Anatomy

A standard split button has two independently operable controls: the main button executes the default action, while the adjacent arrow button opens the menu. Opening the menu does not execute the default action.

1. **Main action:** the default action a user can take.
2. **Arrow button:** contains a chevron-down icon and triggers the menu.
3. **Supplementary actions:** lower priority actions displayed in a menu.

### Layout

- Use `SegmentedButtonGroup` to lay out the separate main `Button` and menu-trigger `Button`. The group does not implement their actions.
- Put the menu-trigger button inside `MenuTrigger` and give it an accessible name that identifies the related commands, such as “More messaging actions”. Use a chevron-down icon to show that it opens a menu.
- Use `Menu`, `MenuPanel`, and `MenuItem` to display supplementary actions. Set the menu's `placement` to `"bottom-end"`. Follow [Menu composition and labels](/salt/components/menu/usage#composition-and-labels) and [action outcomes](/salt/components/menu/usage#action-outcomes).

## Split button affordance

You can use accented solid buttons, neutral solid buttons and transparent buttons in a split button pattern. See guidance for [button options](/salt/components/button) to select the most suitable ones for your application. The example at the top of this page uses neutral solid buttons.

<GuidanceCallout type="positive" customPillText="Best practices">
  Don’t mix the button variants in the same split button.
</GuidanceCallout>

Set `sentiment="accented"` on both buttons for an accented split button.

## Icon-only

The main action is represented by an icon-only button to minimize the width of the entire split button. In the example below, a tooltip labels the icon.

<GuidanceCallout type="positive" customPillText="Best practices">

- Avoid using an icon-only split button if your target audience is unlikely to recognize the proposed icons.
- Use a textual label if your main action is high priority. This ensures users are more likely to see it.
- Use a [tooltip](/salt/components/tooltip) to describe or label the action.

</GuidanceCallout>
