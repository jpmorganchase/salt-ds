## When to use

Use vertical navigation to organize multiple sections of an application into a vertical hierarchy. The navigation pane can remain alongside the content when space allows.

Use it when:

- you need multiple top-level categories that represent the main sections of your website or application
- the information architecture is complex enough that a horizontal nav would be crowded
- the navigation should remain visible as the user moves through nested content
- clear labels or icons can help users scan the hierarchy quickly
- grouped preferences need categories that lead into settings with a Back action on narrow layouts, as in the [preferences dialog pattern](./preferences-dialog)

## When not to use

- When the page only needs a small number of top-level destinations, use a simpler horizontal navigation or app header.
- For a flat set of distinct content panels on the same page, such as Details and History, use [`Tabs`](/salt/components/tabs).
- For headings within one continuous page, use an anchor-style table of contents; see [secondary navigation](#secondary-navigation).
- For a single focused task that does not need section navigation, use a dialog or drawer. Grouped preferences can use the [preferences dialog pattern](./preferences-dialog).

## How to build

### Anatomy

A vertical navigation uses the `VerticalNavigation` component family in a navigation pane:

1. [`VerticalNavigation`](/salt/components/vertical-navigation): Labels the navigation region and owns the item list.
2. [`VerticalNavigationItem`](/salt/components/vertical-navigation/examples): Represents a destination or expandable group. Only one destination should be active at a time.
3. [`VerticalNavigationSubMenu`](/salt/components/vertical-navigation/examples#submenus-collapsible): Contains nested items revealed by an expandable parent trigger. The expansion trigger opens the group rather than navigating.

You will typically use vertical navigation in a sidebar, on the left side of the screen, within a [drawer](/salt/components/drawer), or a [parent-child layout](/salt/components/layouts/parent-child-layout).

### Layout

`VerticalNavigation` owns the column layout and spacing between its items. Keep the hierarchy wide and flat.

## Group (single level)

A single-level vertical navigation group provides a simple list of links that users can select within an application or website. Use `VerticalNavigationItem` with a destination-backed trigger for each link.

## Nested group (multilevel)

Nest `VerticalNavigationItem` entries inside `VerticalNavigationSubMenu` to create a multilevel structure.

Top-level hierarchy items labels use a strong font weight, and nested items use a regular font weight.

<Diagram
  src="/img/patterns/vertical-navigation/vert-nav-nested.png"
  alt="A multi-level vertical navigation group"
  border
  caption="A multilevel vertical navigation group."
/>

<GuidanceCallout type="positive" customPillText="Best practices">

- Surface the hierarchy of your application’s information architecture to as few levels as possible. Maintain a wide and flat hierarchy instead of one that is deep and overwhelming.
- When a parent has a single expansion trigger, activating it expands the group rather than navigating. Put any overview destination first in the group, without a chevron. A parent can instead have a destination link and a separate expansion control.

</GuidanceCallout>

## Secondary navigation

You can use `VerticalNavigationItem` triggers as anchor links within an application view, allowing users to navigate swiftly between various sections on a page. Typically, it functions as a top-level table of contents for the application.

We recommend using a density that is one size smaller than the main navigation. This is particularly applicable when:

- It isn't the primary means of navigation for the entire application and doesn't need the same level of prominence as, for instance, the left-hand navigation.
- A smaller density helps visually signify its hierarchy within the page.

## Within modals

Preferences dialogs can use `VerticalNavigation` to move between grouped settings sections. On wide layouts the categories remain alongside the content; on narrow layouts users open a section and use Back to return to its category. Use [`Tabs`](/salt/components/tabs) for a flat set of local panels such as Details and History.

Refer to the [preferences dialog](./preferences-dialog) pattern for further guidance on how to manage navigation within application preferences modals.

## Responsive behavior

A vertical navigation remains fixed in width when the user resizes the browser. You can set it to the width of your choice, but you should consider the overall label length, theme, density, and screen size you are designing for when making your decision.
