## When to use

Use filtering when you have a lengthy list that users have to scroll to view all available options. The pattern typically comprises input and list based components to use a string to filter items for quick selection.

List filtering is a common behavior found in:

- [`ComboBox`](/salt/components/combo-box)
- [List builder](/salt/patterns/list-builder)
- Pivot table
- Tree builder

## When not to use

- When the user needs to search across broader content or pages, use Search instead.
- When the page is primarily a dashboard or table shell, keep the filter controls in that owning layout instead of using List filtering as the page pattern.
- When the set of options is small and fixed, use Dropdown or another selection control instead.

## How to build

Build the filtering flow around filter logic, no-match feedback, highlighted matching characters, and loading feedback for slow results.

## When to apply filtering

Apply fast local filters as the user changes criteria when results can update promptly. For costly remote queries or several criteria intended to work together, provide an explicit **Apply** or **Search** action instead of requesting results after every field edit.

With explicit submission, distinguish edited criteria from the criteria currently applied to the results. Indicate unapplied changes, including after clearing or resetting controls. Label the scope: filtering only the loaded page is different from filtering the whole collection.

The application owns filtering, fetching, and request timing. Salt controls do not supply that logic; see [ComboBox filtering and submitted values](/salt/components/list-box/usage#filtering-and-submitted-values).

## Clearing and selection

A clear action within one input clears that criterion. A separate **Clear filters** or **Reset all** action restores the documented baseline across the filter controls. Do not clear unrelated criteria when the user clears one field.

In a worklist, filtering must not silently discard selected records or unsaved edits. If filtering hides a selected record, show that the selection is retained and provide a way to reveal it or clear the relevant filters. Make any required selection change explicit.

Selection controls have their own behavior. In a single-select `ComboBox`, clearing the input also clears its selection. When controlling the component, manage input text and selected values through their respective callbacks; see [controlled and uncontrolled ComboBox behavior](/salt/components/combo-box/usage).

## Focus and result updates

Keep keyboard focus in the filter control while results update. When a clear button clears an input, return focus to that input. Do not move focus into the results just because they have arrived.

The application should announce a useful result count or no-match message politely after updates settle, rather than announcing every keystroke or reading the whole list. Avoid competing announcements. A response to an older query must not replace results for a newer query. Follow [Content status guidance](/salt/patterns/content-status#choosing-how-to-communicate-loading-and-recovery) for loading, retained results, and failures.

## Filter logic

When filtering results, we recommend:

- Case-insensitive matching, i.e., Alabama, alabama, ALAbama, will all return the same result.
- Matching only the first character(s) of the beginning of any word in the item labels to the filter string.

## No matches

When filtering completes successfully with no matching items, display an explanatory message instead of the list. Keep the active criteria visible so the user can adjust or clear them. A successful no-match result does not need Retry; a failed request is not a no-match result. Follow [Content status guidance](/salt/patterns/content-status#empty-and-no-matching-results) to distinguish these states.

## Highlighted characters

When filtering, highlight matching characters in item labels that match the filter criteria. This tells a user why the filter returned a given item.

<GuidanceCallout type="positive" customPillText="Best practices">
  Make sure that the text in the list that matches the filter string is
  displayed in `--salt-text-fontweight-strong` font weight.
</GuidanceCallout>

## Loading

When filter matches take longer to return, display a loading message and a [spinner](/salt/components/spinner) in the field. An example is when the system needs to fetch data from a server.
