## Using the component

For further details on how to use the component to provide navigation, see the [navigation pattern](/salt/patterns/navigation/)

<Callout variant="secondary" status="warning">

Use [`VerticalNavigation`](/salt/components/vertical-navigation) for new
vertical navigation. `NavigationItem` can remain in existing vertical
implementations during migration, but we recommend moving to
`VerticalNavigation` because it provides a more structured approach and
`NavigationItem` vertical usage will be deprecated in a future release.

</Callout>

### Routing libraries

If your app uses a routing library such as [React Router](https://reactrouter.com/en/main) or [Next.js](https://nextjs.org/docs/app/building-your-application/routing), use the `render` prop to render the routing library’s link component. See the [render prop guide](/salt/getting-started/render-prop) for the supported render forms.

### When to use

- When users navigate to distinct pages or applications through a horizontal group of destination links.
- If a horizontal group cannot comfortably fit your destinations or you need a nested hierarchy, use [`VerticalNavigation`](/salt/components/vertical-navigation).
- If you need your items to remain visible on scroll, we recommend displaying navigation items in a fixed app header (or header area).

### When not to use

- When you are creating new vertical navigation. Use [`VerticalNavigation`](/salt/components/vertical-navigation) instead.
- When users switch between a flat set of distinct content panels on the same page, such as Details and History. Use [`Tabs`](/salt/components/tabs/). For responsive settings section navigation, use `VerticalNavigation` with the [preferences dialog pattern](/salt/patterns/preferences-dialog).
- When users switch the same underlying records between List and Cards. Use [`ToggleButtonGroup`](../toggle-button/usage#view-switching) for that presentation choice.
- When your content is very specific. In this case, a minimalistic or single-page design may be more appropriate than a complex navigation structure. Use [`LinkCard`](../card/examples#link-card) or [`Link`](../link) for destinations within the body of the page.

## Content

- To make the most of screen real estate, our recommendation is that all description text should be clear and concise.
- Always write descriptions in sentence case in a navigation item.
- When using a navigation item component within a navigation item, we recommend using sentence case.
- In a horizontal navigation item, do not wrap descriptions, use truncation with `Tooltip` if necessary.
- In a vertical navigation item, descriptions can wrap onto multiple lines if necessary, and is preferred over truncation.

## Import

To import `NavigationItem` from the core Salt package, use:

```js
import { NavigationItem } from "@salt-ds/core";
```
