## Using the component

Position the banner in the area its message concerns. Place page-wide feedback below the page navigation. For feedback about a form, dialog, or section, place it within that container near the affected content. Span the available content width.

Keep a banner available while its information or recovery actions are needed; do not dismiss it automatically on a timer. Configure it to close when:

- The user resolves the issues described in the message, such as correcting all errors in a validation summary.
- The system status that triggered the notification is resolved, such as restoring a server connection.

### When to use

- To keep feedback visible alongside the task or content it concerns, especially when the user needs to understand or resolve an issue.
- To explain a failed save within the affected form or dialog. Preserve entered values and provide appropriate recovery, such as retrying. A service or network failure does not make valid fields invalid. See [submission and recovery](/salt/patterns/forms#submission-and-recovery).
- To summarize form validation errors while retaining specific feedback at each affected field. See the [error summary pattern](/salt/patterns/forms#error-summary).
- To explain a failed refresh while keeping previously loaded content visible in the related container. See [choosing how to communicate loading and recovery](/salt/patterns/content-status#choosing-how-to-communicate-loading-and-recovery) for the distinction between Banner, Content status, and local loading feedback.

### When not to use

- For essential platform-wide notices, such as maintenance or an outage affecting the application, use [`SystemStatus`](../system-status/usage).
- For a brief, nonblocking confirmation or peripheral update that does not need to remain beside the affected content. Consider [`Toast`](../toast), provided it is not the only place to find essential information or recovery actions.
- As a replacement for feedback associated with an invalid field. Use [`FormField`](../form-field) feedback; a banner summary can supplement it.

## Content

A banner typically has one or two lines of text. Make content short, clear, and concise, allowing users to quickly scan the notification and understand the situation and/or next steps.

Body Default applies to the content, however, if titles are necessary, configure them to display the Body Strong typography style across densities. See the [typography foundation](/salt/foundations/typography/) for more information.

## Import

To import `Banner` and related components from the core Salt package, use:

```js
import { Banner, BannerContent, BannerActions } from "@salt-ds/core";
```
