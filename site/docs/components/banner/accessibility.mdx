## Best practices

`Banner` does not add an announcement role or live region, or move focus automatically. Its `status` controls appearance, not announcement urgency. Describe the issue and any recovery action in text rather than relying on color or the status icon.

For dynamic feedback, use `role="status"` for a polite update or `role="alert"` when the message needs immediate announcement. Choose the announcement behavior for the situation; an error does not always require an assertive announcement. Avoid duplicating feedback already announced by another live region or focus change. For form validation, follow the [error summary pattern](/salt/patterns/forms#error-summary).

Test dynamic announcements with the browsers and screen readers you support. If a newly inserted `role="status"` region is not announced, mount an empty live region before updating its content and test again.

Check keyboard access to any links and actions included in the banner. Adding an announcement role does not make its actions receive focus.
