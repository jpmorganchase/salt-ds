## Best practices

Check and test any focusable elements included in the system status content.

A system status doesn't have a live region role. A system status that's present when the page loads doesn't need one, because screen readers don't announce live region content that's on the page when it loads. To let screen reader users navigate to it, add `role="region"` and an `aria-label`, as shown in the [placement example](/salt/components/system-status/examples#placement).

If you add a system status after the page loads, or show it again after it's dismissed, render it inside a container with `role="alert"` for an error system status, or `role="status"` for all other statuses. Add the container when the page first loads, then render the system status inside it. See the [announced example](/salt/components/system-status/examples#announced).

- **Note:** During your testing, check that the system status is announced using a screen reader.

### Accessible names for actions

Give every action in a system status an accessible name that describes what it does. An icon-only close button needs an `aria-label`, such as "Dismiss system status".

### Focus after dismissal

A system status doesn't manage focus. When a user dismisses it, move focus to the control that showed the system status. If there isn't one, for example because the system status was present when the page loaded, move focus to the next logical element. Otherwise, focus is lost when the system status is removed from the page. See the [announced example](/salt/components/system-status/examples#announced).
