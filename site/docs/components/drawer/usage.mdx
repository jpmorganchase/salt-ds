## Using the component

Drawers are always modal. This means that the content behind them is inert and can't be interacted with. A [`Scrim`](../scrim) is used to visually obscure the content behind the drawer.

Compose a drawer from `DrawerHeader`, `DrawerContent` and `DrawerFooter`. `DrawerHeader` stays pinned to the edge the drawer is anchored to, `DrawerContent` scrolls when its content overflows, and `DrawerFooter` stays pinned to the bottom of the drawer. Pass a close `Button` to the `actions` prop of `DrawerHeader`.

`DrawerHeader` names the drawer using its `header` and `preheader`, and describes it using its `description`, so you don't need to set `aria-labelledby` or `aria-describedby` manually.

Left and right drawers cover the entire height of the viewport, and top and bottom drawers cover its entire width.

Always set a logical width suitable for the content inside the drawer. Refer to Salt's [Forms](/salt/patterns/forms) pattern for information on logical forms width, and the [typography foundation](/salt/foundations/typography) for guidance on paragraph text width.

### Resizing

Use the `resizable` prop when the right size depends on the user's content or screen, such as a drawer containing a table or a chart. Bound the resize with `minSize` and `maxSize` so the drawer stays usable, and use `onResize` if you need to persist the size the user chose.

A resizable drawer does not scroll itself, so compose it from `DrawerHeader`, `DrawerContent` and `DrawerFooter` and let `DrawerContent` scroll.

The resize handle matches the handle used by [`Splitter`](/salt/components/splitter). A drawer is modal and temporary, so it is resized on its own against the edge of the screen; to split a persistent layout between regions that stay visible, use `Splitter`, and for a persistent resizable region alongside the main task use [`SidePanel`](/salt/components/side-panel).

### When to use

- To complete quick, self-contained actions with minimal disruption, such as quick selections, lightweight submissions, or confirmations, then return to the prior context.
- To present on-demand, contextual supporting content or controls (e.g., short forms, secondary actions, or relevant information) that can be dismissed when no longer needed.

### When not to use

- For ongoing parallel work that benefits from persistent visibility.
- If supporting information and controls should remain available while the main task continues (e.g., referencing details, inspecting data, filtering results, editing attributes), use [`SidePanel`](/salt/components/side-panel) instead.

## Import

To import `Drawer` and related components from the core Salt package, use:

```js
import {
  Drawer,
  DrawerContent,
  DrawerFooter,
  DrawerHeader,
} from "@salt-ds/core";
```
