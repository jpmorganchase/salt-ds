Salt layouts manage the structure and arrangement of interface regions rather
than supplying product content themselves. They provide reviewed spacing,
alignment and responsive behavior over CSS Grid and Flexbox.

<Callout>
  Salt does not provide a Figma equivalent for these layouts. Instead, Figma
  offers auto layout functionality, which serves a similar purpose in design
  tools by controlling the arrangement and responsiveness of elements.
</Callout>

Salt layout components are each tailored to specific structural needs:

{meta.data.items?.map(({ title, data }, index) => <div style={{ marginTop: 'var(--salt-spacing-100)' }} key={`${title}-${index}`}><Text styleAs="h2">{title}</Text>{(data?.description?.replaceAll("`", "").match(/^.*?\./)?.[0]?.trim() || data?.description?.replaceAll("`", "").trim() || "")}</div>)}

<Callout title="Layout review checklist">

- Prefer a Salt layout before adding a generic wrapper with custom CSS.
- Each extra container should have a clear structural job such as flow, split,
  stack, grid, or parent-child arrangement.
- Use [`DeckLayout`](./deck-layout) when one region displays one page at a time.
- Use [`LayerLayout`](./layer-layout) only for a bespoke overlay shell; prefer
  Salt's established dialog, drawer, tooltip or menu components when their
  behavior matches the task.
- `DeckLayout` and `LayerLayout` come from `@salt-ds/lab` and are experimental.
  Review their release notes before upgrading.

</Callout>

## Accessibility and keyboard behavior

A layout does not define the reading order or keyboard contract of the content
inside it. Keep DOM order meaningful, preserve visible focus, and test zoom,
reflow and keyboard navigation at every supported breakpoint. Overlay and deck
layouts have additional focus and naming responsibilities described on their
component pages.
