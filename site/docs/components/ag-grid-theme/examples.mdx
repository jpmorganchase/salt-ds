<AGThemeProvider>

These examples show how Salt styles AG Grid and how to compose Salt controls with AG Grid behavior. Start with [Set up](./usage#set-up). Salt provides the visual theme, not data loading, filtering logic or application state. The examples register AG Grid Enterprise; examples requiring an Enterprise license are identified below. The others work with Community.

## Appearance

### Default

Applies the default look when applying the Salt theme.

</Callout>

### Variants

The Salt AG Grid theme supports three variants: primary (default), secondary and tertiary. Each variant adjusts the background color of the data grid, providing options to support the creation of a visual hierarchy. To use one of the non-default variants, add `ag-theme-salt-variant-secondary` or `ag-theme-salt-variant-tertiary` to the container element, next to the theme class name.

<LivePreview componentName="ag-grid-theme" exampleName="Variants" />

### Zebra

`ag-theme-salt-variant-zebra` alternates row colors to improve readability. This is particularly useful for large datasets where distinguishing between rows can be challenging.

The color of the alternating rows is determined by the variant:

- primary variant uses the secondary background for alternating rows.
- secondary variant uses the primary background for alternating rows.
- tertiary variant uses the primary background for alternating rows.

<LivePreview componentName="ag-grid-theme" exampleName="Zebra" />

### Header variant

Header variants create a visual distinction between the header and the body of the data grid. Add one of these class names to the container element:

- `ag-theme-salt-header-primary`
- `ag-theme-salt-header-secondary`
- `ag-theme-salt-header-tertiary`

<LivePreview componentName="ag-grid-theme" exampleName="HeaderVariants" />

### HD Compact

`ag-theme-salt-compact` is an opt-in presentation for specialized high-density grids, not another Salt density. This example applies it only in high density; the class itself retains its compact sizing for compatibility at other densities. The status bar and cell selection shown here require AG Grid Enterprise.

<LivePreview componentName="ag-grid-theme" exampleName="HDCompact" />

### Coloration

You can apply custom color to cells with `cellStyle` or `cellClass`. Each cell leaves a 1px gap on its right, so neighboring colored cells stay separate. Set the color with `backgroundColor` rather than the `background` shorthand, which also paints the gap.

<LivePreview componentName="ag-grid-theme" exampleName="Coloration" />

### Pagination

Users can move between pages using the controls in the lower right.

The example below suppresses AG Grid's built-in pagination panel and composes Salt controls around AG Grid's pagination state. AG Grid owns the pages of generated local rows; the example synchronizes the active page, page count, page size, and displayed range with the grid. It does not implement remote data loading. When adapting it for remote data, decide whether AG Grid or your application owns pagination state, and keep the controls in sync with the actual page and result count.

<LivePreview componentName="ag-grid-theme" exampleName="Pagination" />

### Infinite scroll

The grid requests additional row blocks as the user scrolls. This example simulates a loading delay by slicing generated local data into blocks. It does not implement remote fetching, filtering, sorting, or failure recovery. For a real data source, handle loading, empty results, errors and retries in your application; the example does not implement those states.

The infinite row model needs an explicit `rowHeight` to resize existing rows when density changes. This example derives it from `useDensity()`, using the heights in [Density](./usage#density), so the grid updates without remounting.

## Interaction

### Checkbox selection

Users can select rows via checkboxes. Make the scope of a bulk selection explicit: loaded rows, the current page, filtered results, or all records, as supported by the grid configuration and data source. Do not imply that unloaded records are selected unless the application supports that operation. When filtering hides selected records or unsaved edits, decide whether selection persists and communicate that behavior to users.

<LivePreview componentName="ag-grid-theme" exampleName="CheckboxSelection" />

### Cell editors

Salt provides styling for a few AG Grid [provided cell editors](https://www.ag-grid.com/react-data-grid/provided-cell-editors/) to best match the Salt theme. It applies when `editable-cell` is in the column's `cellClass` and the column's `cellEditor` is one of AG Grid's `ag*CellEditor` editors, so it doesn't affect your own cell editors.

The [Rich Select Cell Editor](https://www.ag-grid.com/react-data-grid/provided-cell-editors-rich-select/) in this example is an AG Grid Enterprise feature; with AG Grid Community, use the [Select Cell Editor](https://www.ag-grid.com/react-data-grid/provided-cell-editors-select/).

You can also pair an editor with one of AG Grid's provided [column filter types](https://www.ag-grid.com/react-data-grid/filtering/#column-filter-types) in the column's `filter`.

<LivePreview componentName="ag-grid-theme" exampleName="ProvidedCellEditors" />

### Cell validation

[Editable cells](#cell-editors) can show validation states (warning, success and error) using the class names `warning-cell`, `success-cell` and `error-cell`. Tell users what's wrong in text as well, such as in a tooltip or a message near the grid: the state's color and icon alone don't say it. This example's Rich Select editor is an AG Grid Enterprise feature.

<LivePreview componentName="ag-grid-theme" exampleName="CellValidation" />

### Row validation

Rows can show validation states (warning, success and error) using the class names `warning-row`, `success-row` and `error-row`, in the grid's `rowClass` or `rowClassRules`.

<LivePreview componentName="ag-grid-theme" exampleName="RowValidation" />
