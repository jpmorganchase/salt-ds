## Best practices

### Accessible name

Keep visible button labels short and action-led. For repeated actions, show
**Inspect** on the button and the record name in its row. Use `aria-label` or
`aria-labelledby` to include the visible label text and record context in each
accessible name; for example, “Inspect Risk calculator”.

Use an icon-only button only when space is limited and users recognize the icon;
otherwise, keep visible text. Give icon-only buttons an `aria-label` describing
the action. Add a Tooltip to explain the icon; it does not replace the accessible
name. Hide decorative icons with `aria-hidden`.

### Focusable disabled button

- By default, a user can't place focus on a disabled button. However in certain scenarios, it may be preferable for a disabled button to receive focus. To determine if this is necessary, you can apply the following logic: if the user or the system can enable a disabled element, it should be focusable. For further information, view the W3C guidance on the [`aria-disabled` attribute](https://www.w3.org/TR/wai-aria/#aria-disabled).

## Keyboard interactions

<KeyboardControls>
<KeyboardControl keyOrCombos="Tab">

- Tab moves focus to the button.
- If the button is disabled and cannot receive focus, Tab moves focus to the next focusable component.
- If the button has focus, Tab moves focus to the next focusable component in the tab order.

</KeyboardControl>
<KeyboardControl keyOrCombos="Shift + Tab">

- This action moves focus out of the component to the previous component in the tab order.

</KeyboardControl>
<KeyboardControl keyOrCombos="Enter / Space">

- If the button has focus, this action activates it.
- If the button is disabled and can receive focus, this action does nothing.

</KeyboardControl>
</KeyboardControls>
