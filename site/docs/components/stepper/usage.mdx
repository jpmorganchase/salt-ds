| ---------- | ----------- | ------------------ | ------------- | ---------- | ------------------- | ------------- |
| Horizontal | 3-6 optimal | Wide layouts       | Left-to-right | No         | Concise (1-2 words) | Below steps   |
| Vertical   | Any count   | Normal/Constrained | Top-to-bottom | Yes        | Can be long         | Beside steps  |

## When to use

- Horizontal stepper: for wide layouts and desktop applications where you want to show all steps simultaneously and let users scan progress at a glance; best with 3–6 steps, relatively basic flows and no nested substeps.
- Vertical stepper: for step-by-step guided experiences that need detailed, multi-line descriptions per step, or expandable (accordion-style) step content; works well with longer label text. Use it for longer, more complex linear flows, where steps benefit from being broken down into more digestible groups.
- Compact stepper: Use Compact Stepper exclusively in dedicated, constrained viewports or linear forms where a simplified progress indicator is required from the start across all supported screen sizes

## When not to use

- Horizontal stepper
  - Avoid in sidebars/panels or narrow containers; it should only be placed above form/page content, not within constrained-width regions.
  - Do not swap Horizontal Stepper with Compact Stepper at smaller viewports/media queries. Dropping step names, descriptions, and statuses upon screen resize or browser zoom (320px / 400% zoom) constitutes an accessibility failure under WCAG 1.4.10 Reflow (Loss of Information).
  - Avoid for longer or more complex flows, or flows with substeps. Instead, use a vertical stepper.
- Vertical stepper
  - Avoid when horizontal space is abundant and steps have minimal content; the extra vertical real estate isn't justified for short, simple step sequences. It should ideally be used in a 2 column page layout
- Compact stepper
  - Avoid when step descriptions or expandable substeps are needed; its condensed format drops detail, so use Horizontal or Vertical instead when more context per step is required
  - Do not use Compact Stepper as a downscaled responsive breakpoint fallback for Horizontal Stepper unless an accessible progressive disclosure pattern (such as an expandable step directory) is provided to prevent loss of step information under WCAG 1.4.10

## Content

- Pass plain text to `label` and `description`. They're combined into the text that screen readers announce, so other content, such as an element, isn't announced correctly.
- Labels and descriptions wrap and never truncate.

## Import

To import `Stepper` and `Step` from the core Salt package, use:

```js
import { Stepper, Step } from "@salt-ds/core";
```

To import `CompactStepper` and `CompactStep` from the lab Salt package, use:

```js
import { CompactStepper, CompactStep } from "@salt-ds/lab";
```
