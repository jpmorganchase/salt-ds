## Best practices

- Provide an accessible name for each stepper with `aria-label` or `aria-labelledby`, for example by referencing the title of the process.
- Set `stage="active"` on only one step. Each active step has `aria-current="step"`.
- If you add a tooltip to a step, don't put essential information in it. Steps can't receive focus, so keyboard users can't open the tooltip.

## Step state

`Stepper` renders an ordered list, and each step is a list item.

Screen readers read each step's label, description and state, such as "completed" or "error". If a step has a status, they read the status instead of the stage. The active step is marked as the current step.

Stages don't change on their own, and changes to them aren't announced. Update them from your application's state when the user moves to another step.

## Substeps

In a vertical stepper, a step with substeps has an expand button. The button has `aria-expanded` and `aria-controls`. Its accessible name is the step's label, description and state, followed by "toggle substeps".

The list of substeps is named after the step's label, followed by "substeps". It's hidden while the step is collapsed.

## Keyboard interactions

Steps can't receive focus. Only the expand buttons of steps with substeps can.

<KeyboardControls>
<KeyboardControl keyOrCombos="Tab">

Moves focus to the next expand button. Expand buttons inside collapsed steps are skipped.

</KeyboardControl>
<KeyboardControl keyOrCombos="Shift + Tab">

Moves focus to the previous expand button.

</KeyboardControl>
<KeyboardControl keyOrCombos="Enter / Space">

Expands or collapses the substeps of the step. Focus stays on the expand button.

</KeyboardControl>
</KeyboardControls>
