## Using the component

For further details on how to use the component to provide navigation, see the [navigation pattern](/salt/patterns/navigation/)

### Routing libraries

If your app uses a routing library such as [React Router](https://reactrouter.com/en/main) or [Next.js](https://nextjs.org/docs/app/building-your-application/routing), use the `render` prop on navigation item triggers to render the routing library’s link component. See the [render prop guide](/salt/getting-started/render-prop) for the supported render forms.

Only provide `href` when the item has a real navigation destination. For an in-page action with no destination, omit `href`; `VerticalNavigationItemTrigger` then renders as a button. Do not ship placeholder destinations such as `href="#"`.

### When to use

- When you need structured vertical navigation. Prefer `VerticalNavigation` over using `NavigationItem` in vertical mode for new implementations.
- When you have multiple levels of navigation in your application or website.
- When grouped settings use category navigation that becomes categories, settings and Back on narrow layouts. Follow the [preferences dialog pattern](/salt/patterns/preferences-dialog).
- When your destinations do not comfortably fit a horizontal group or you need space for a nested hierarchy. Use a persistent navigation pane if the items need to remain visible while the page content scrolls.

### When not to use

- When a horizontal group of destination links suits the application structure and available space. Use [`NavigationItem`](../navigation-item).
- When users switch between a flat set of distinct content panels on the same page, such as Details and History. Use [`Tabs`](/salt/components/tabs/). This differs from the responsive settings sections with a Back action in the [preferences dialog pattern](/salt/patterns/preferences-dialog).
- When users switch the same underlying records between List and Cards. Use [`ToggleButtonGroup`](../toggle-button/usage#view-switching) for that presentation choice.
- When your content is very specific. In this case, a minimalistic or single-page design may be more appropriate than a complex navigation structure. Use [`LinkCard`](../card/examples#link-card) or [`Link`](../link) for destinations within the body of the page.

## Content

- To make the most of screen real estate, our recommendation is that all description text should be clear and concise.
- Always write descriptions in sentence case in a navigation item.
- When using a navigation item component within a navigation item, we recommend using sentence case.
- Descriptions can wrap onto multiple lines if necessary; this is preferred over truncation.

## Import

To import `VerticalNavigation` and related components from the core Salt package, use:

```js
import {
  VerticalNavigation,
  VerticalNavigationItem,
  VerticalNavigationItemContent,
  VerticalNavigationItemExpansionIcon,
  VerticalNavigationItemLabel,
  VerticalNavigationItemTrigger,
  VerticalNavigationSubMenu,
} from "@salt-ds/core";
```
