## Best practices

- Screen reader users will use the <kbd>Tab</kbd> key to jump from link to link or pull up a list of links on a page. Avoid using the same link text to link to different content and ensure that links make sense out of context.
- Ensure the link's accessible name identifies the destination. If you add an `aria-label` or `aria-labelledby` for extra context, include the visible link text in that name.
- Prefer the default underline as a persistent, non-color cue that text is a link. If you remove the underline, make sure the link is recognizable from its context or another visible cue; do not remove underlines from inline links in paragraphs or other text-heavy content.
- When a link contains an icon and text, pass `aria-hidden` to the icon so that its label is not announced by screen readers.
- When a link has an icon and no visible text, pass an `aria-label` to the link to describe the content that the link leads to.
- When `target="_blank"` is set, `Link` automatically adds a visual icon and visually hidden text to communicate that the destination opens in a new tab. Keep the default icon for standard text links; use `IconComponent={null}` only when composed or custom content already provides another visible cue.
