## Using the component

### When to use

- When users need to select one or more values and the list of options does not need to stay visible.
- When available space favors a popup and users can find the options without typing a filter. Use `multiselect` when multiple values are allowed.

### When not to use

- When typing would help users find an option. Instead, use [`ComboBox`](../combo-box) and supply the filtering logic.
- When users should compare a small set of mutually exclusive choices without opening a popup. Instead, use [`RadioButtonGroup`](../radio-button).
- When multiple independent choices should remain visible together. Instead, use [`CheckboxGroup`](../checkbox).
- When a selectable list should remain visible. Instead, use [`ListBox`](../list-box).
- For a popup list of actions such as Edit or Delete. Instead, use [`Menu`](../menu).
- For an on/off setting that takes effect immediately. Instead, use [`Switch`](../switch).

See [Choosing a selection control](../list-box/usage#choosing-a-selection-control)
for the decision and the distinction between filtering and large-list performance.

### Controlled/Uncontrolled

By default, a dropdown manages its own selection. Use `defaultSelected` to set the
initial selection, or `selected` with `onSelectionChange` to control it.

The `value` prop overrides the text displayed in the button, for example to show a
summary of multiple selected options. It does not replace `selected` as the
selection state.

## Import

To import `Dropdown` from the core Salt package, use:

```js
import { Dropdown, Option, OptionGroup } from "@salt-ds/core";
```
