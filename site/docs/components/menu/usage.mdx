## Using the component

- Menu items should relate to the interactive element or interaction that triggers the menu.

### When to use

- When you need a popup list of commands related to the trigger or its content.
- When space is limited and secondary actions can be collected in an overflow menu.
- When actions need grouping or submenus to make related commands easier to find.

### When not to use

- When the user is choosing a form value. Use a selection control such as [`Dropdown`](../dropdown), [`ComboBox`](../combo-box), or [`ListBox`](../list-box); see [choosing a selection control](../list-box/usage#choosing-a-selection-control). A menu may still expose actions alongside form fields.
- For persistent presentation choices such as List and Cards, follow [view switching](../toggle-button/usage#view-switching). `Menu` does not provide selected-value behavior.
- For application destinations, follow the [Navigation pattern](/salt/patterns/navigation) and its link and navigation component choices.

### Choosing an action control

- Use [`Button`](../button) for an action the user can invoke directly.
- Keep important actions visible in a [Button bar](/salt/patterns/button-bar) or [`Toolbar`](../toolbar) when users need frequent access to them.
- Use a [Menu button](/salt/patterns/menu-button) when its trigger only opens a list of commands; it does not execute a separate default action.
- Use a [Split button](/salt/patterns/split-button) when a default action and a menu trigger should be independently operable.

### Composition and labels

Compose `Menu` with a `MenuTrigger` containing a `Button`, and a `MenuPanel` containing `MenuItem` actions. Use `MenuGroup` to label or separate related commands. For a submenu, nest a `Menu` whose `MenuTrigger` contains the parent `MenuItem`; see the [multilevel example](./examples#multilevel).

Keep each menu item as one action; do not put additional buttons, links, or form controls inside it. Visible trigger and item labels should remain in their accessible names. Give repeated icon-only triggers a contextual name identifying the row or content, such as “Actions for Order Gateway”, so users can distinguish them. Follow the [keyboard guidance](./accessibility#keyboard-interactions).

### Action outcomes

The examples illustrate composition; connect each command to an application action. The application owns each menu command’s execution, progress feedback, and failure recovery. Closing the menu does not establish that an action succeeded. Keep essential failure details and recovery actions available in the affected content; follow [Forms feedback guidance](/salt/patterns/forms#choosing-feedback) for form actions and [Content status guidance](/salt/patterns/content-status#choosing-how-to-communicate-loading-and-recovery) for loading or refreshing content.

### Opening a dialog

A menu command can open a dialog to collect more information or confirm an action. Keep the dialog outside the menu panel so closing the menu does not unmount it. Activating the command should close the menu and move focus into the dialog; for destructive confirmation, give Cancel initial focus.

The menu item is a temporary focus target. Plan where focus returns on Cancel or Escape and where it moves if the action removes the record. Follow [Dialog return-focus guidance](../dialog/accessibility#returning-focus-after-an-action) and its current API limitation. Verify the menu-to-dialog handoff with both keyboard and pointer activation; rendering the two components together does not establish correct focus behavior.

For deletion, follow [Destructive actions](../dialog/usage#destructive-actions) for pending requests, failure, recovery, and success. Opening the dialog and closing the menu do not execute or complete the deletion.

## Content

- Always use sentence case for menu item labels.
- Keep menu item labels short and concise.
- Use an ellipsis at the end of a menu item label for actions that will require more information from the user to complete. For example, "Open file..." requires the user to choose a file.

## Import

To import `Menu` and related components from the core Salt package, use:

```js
import {
  Menu,
  MenuItem,
  MenuTrigger,
  MenuPanel,
  MenuGroup,
} from "@salt-ds/core";
```
