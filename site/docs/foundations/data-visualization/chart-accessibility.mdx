Charts rely on visual elements to make complex data easier to understand, so it’s essential they are accessible to everyone. Ground your chart design and implementation in the [WCAG POUR principles](https://www.w3.org/WAI/fundamentals/accessibility-principles/):

- **Perceivable**: Text equivalents (caption, summary), accessible data table, sufficient contrast, labels/patterns/markers instead of color alone.
- **Operable**: Full keyboard access, predictable focus order, non-hover-only interactions, pause/stop controls for animation, adequate target sizes.
- **Understandable**: Clear titles and legends, consistent scales/units, plain language, concise insight summaries, predictable behavior.
- **Robust**: Semantic markup, ARIA roles and names, programmatic relationships, compatibility with screen readers, cross-browser testing and fallbacks.

## Color contrast

Color contrast is essential for the readability of charts, especially for people with low vision or color deficiencies. The use of custom colors or hex codes is discouraged, as they may not meet WCAG non-text contrast requirements. Salt tokens are designed to achieve at least a 3:1 contrast ratio between the background and non-text chart elements such as bars, lines, segments, and icons. This does not mean categorical colors are distinguishable from each other: a separate visual cue may still be needed to identify series.

## Visual affordances

Under [WCAG 1.4.1 Use of Color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color), color cannot be the only visual way to distinguish information. A color-coded legend alone does not solve this if users must still distinguish hues to match the legend to the chart. Choose a visible alternative appropriate to the data:

- Direct labels on lines, areas, segments, or points
- Distinct marker shapes or line styles, with matching legend keys
- A fixed series position or order, explicitly described in text
- Different shapes or fills, such as hollow and solid candlesticks
- Line or fill patterns when the other cues are unsuitable

Use borders with at least a 3:1 contrast ratio against adjacent fills when boundaries are needed to understand the chart. Borders can separate segments but may not identify which series each segment represents.

Screen reader descriptions, keyboard navigation, and tooltips remain important, but do not replace the visible alternatives required by WCAG 1.4.1. For dense charts, consider an additional visible summary or data table.

## Pattern fills

Use pattern fills for two-dimensional shapes, such as bars and slices, when their meaning would otherwise depend on color. Pattern fills should always be black as they are applied over solid categorical colors in charts. They are particularly useful for dense or stacked charts where visible labels would become crowded, but are not mandatory when another visual cue communicates the same information.

Learn more about the available pattern fills in the [Color and pattern page.](/salt/foundations/data-visualization/color-and-pattern)

## Marker symbols

Use marker symbols to make data points more distinctive and help differentiate lines. Marker symbols have a white border in both light and dark modes for accessibility. If you have more than five data series, the additional series will simply use the first symbol again. The symbols cycle through the available options, so for a sixth series, it would revert back to the first symbol in the defined set.

Salt uses predefined symbols in the following order:

- Circle
- Diamond
- Square
- Triangle (up)
- Triangle-down

## Text formats

Assistive technology users typically navigate charts using screen readers or keyboards—and may not be able to perceive every visual element or navigate a complex chart easily. Consider whether the complexity of your chart warrants a text description or an equivalent format.

There are several things you could add to aid the understanding of your chart:

- A chart name
- A chart summary
- A progressive disclosure or an overlay containing a further description
- Data table or list in addition to the chart
- A link to a nearby page

A simple pie or donut chart with a small number of data points and no trends, for example, may not require a text equivalent, provided keyboard and screen reader users can perceive all the data points.

As a last resort, you can link to a nearby page via a link next to the chart. Try to keep these links adjacent to their respective chart, as placing essential information on a separate screen will disrupt the flow of information and increase unnecessary cognitive load.

For more information about alternative formats, read the [JPMC UX Accessibility Resources](https://go/text-alternatives#TextAlternatives-Compleximages) (Internal users only).
